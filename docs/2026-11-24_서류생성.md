| 구간 | 전기 `eung` | 통신 `tongsin` | 소방 `sobang` |
| --- | --- | --- | --- |
| LH 50억 미만 | ×1 | ×1 | ×1 |

실적계수는 공통 기준에 따라 소수 둘째 자리 반올림 후 ×13, 실적 배점 상한 적용, 점수 반올림을 한다. 품질 합산 후 시공경험 상한은 15점이다.

### 품질평가: 최종 확정한 방식

2026-11-27 사용자의 정정에 따라 LH 50억~100억은 **업체별 원점수 × 지분을 합산한 다음, 합산점수에 해당하는 등급·평점을 적용**하는 원래 방식으로 복원했다. 업체별 등급점수를 먼저 구해 지분으로 합산했던 이전 지시는 철회되었다.

- A: 90점 이상 → 5점
- B: 88점 이상 → 3점
- C: 85점 이상 → 2점
- D: 83점 이상 → 1.5점
- E: 80점 이상 → 1점
- F: 80점 미만 → 0점

예: `93.38점 × 51% + 85점 × 49% = 89.2738점`이므로 B등급 3점이다. 양식에는 업체별 원점수와 가중합 산식·결과, 최종 등급을 출력한다. 미평가 업체는 기존 규칙대로 85점을 적용한다.

버튼·별도 적용 플래그 없이 기존 서류를 열 때도 `weighted-grade`로 저장된 품질 합산 방식만 `weighted-raw`로 복원한다. 총괄의 시공경험·소계·총점도 복원 결과를 반영한다. 실적 분모·배점 등 다른 저장 기준은 유지한다. 원래 원점수 합산 방식으로 저장된 서류는 그대로 유지하며, 불러오기·미리보기만으로 원본 저장파일을 덮어쓰지 않는다.

협정보드의 LH 50억~100억 품질 합계는 원점수 가중합을 표시하고, 평점 및 협정 엑셀 내보내기 데이터도 같은 공통 계산을 사용한다. LH 50억 미만과 LH 100억~300억 방식은 유지한다.

### 3. 경영상태평가: 업체별 드롭다운 선택

유효한 신용이 있으면 무조건 나목을 쓸지 질문했으나, 최종적으로 사용자가 **업체별로 평가방법을 선택하는 드롭다운**을 원했다. 현재 선택지는 다음 세 가지다.

- `auto`: 자동 선택(높은 점수). 기존 공통 평가처럼 신용·재무 중 높은 점수, 동점이면 재무비율.
- `composite`: 재무비율 평가, 가목을 직접 지정.
- `credit`: 신용평가, 나목을 직접 지정.

선택은 업체 카드의 **경영상태 평가방법**에 있으며 `managementMethod`로 저장한다. 예전 저장 서류에 값이 없으면 `auto`로 해석한다. 업체 정보 재선택은 새 업체로 교체하므로 기본값으로 돌아가지만 경영정보만 새로 불러오기는 선택값을 유지한다.

공통 계산기로 두 방식의 점수를 산출하고, 직접 지정한 방식의 점수를 신청서 문구·총괄·경영 상세표에 함께 사용한다. 협정보드의 전역 평가 선택 규칙은 변경하지 않았다.

- 신용평가 없음·만료: 자동 선택에서는 부채비율·유동비율·영업기간으로 평가한다.
- 신용평가를 직접 지정했는데 만료·등급 없음: 재무비율로 몰래 바꾸지 않고 **미산정과 보완 문구**를 표시한다.
- 가목을 직접 지정했는데 재무정보 부족: 미산정으로 표시한다.
- 유효기간 판정 기준일은 공고일이다. 기존 공통 신용 유효성·만료 플래그 판정을 사용한다.
- 가목을 사용하지 않는 업체의 가목 칸은 `-`, 나목을 사용하지 않는 업체의 나목 칸도 `-`다.

부채·유동비율의 업종평균, 영업기간, 신용등급표는 저장된 신청서 평가 기준을 사용한다. 가목 원본은 45점 표이고 공통 계산은 15점으로 정규화되어 있으므로, 현재 LH 50억~100억 상세 양식은 `financialFormScale: 3`으로 원점수를 표시한다. 이 표시 배율을 50억 미만에 그대로 복사하지 않는다.

**계산식 표시에서 `환산 15점` 같은 문구를 쓰지 말라는 사용자 수정도 반영했다.**

```text
가목 예시
㈜영화전력 : 22 +21 +2 = 45점

나목 예시
```

동일 원점수·동일 평가점수인 업체는 지분을 합쳐 표시하고, 점수가 다르면 항을 나눠 표시한다. 표시 코드는 공통 평가 결과를 사용하며 점수·반올림 로직을 다시 만들지 않는다.

### 4. 신인도 평가

2026-11-27 수정: LH 50억~100억은 `서류양식/LH_적격심사_50억~100억_신인도.pdf`를 기준으로 `lh50To100Credibility.js`에 양식을 분리했다. 사고사망만인율(+3), 산업재해 예방 활동 실적(+2), 중대재해(-5), 안전보건경영시스템 인증(+1), 마지막 `<삭제>` 행을 포함한 14개 행과 표 안 합계를 출력한다. 기존 행의 심사항목명과 하도급 각주도 원본에 맞췄다. 하도급 심사항목은 두 행을 병합하고, 등급별 평점을 해당 등급의 첫 줄에 맞춘다. 7개 행씩 두 페이지에 배치하여 행 중간의 페이지 분할을 피한다. `<삭제>` 행의 업체 점수는 공란이며 나머지 업체 점수·합계는 계속 0점이다. 저장된 이전 양식은 열 때 양식만 갱신하며 기존 평가기준과 계산점수는 보존한다. LH 50억 미만은 별도 양식을 계속 사용한다.

사용자가 추후 수정 요청 전까지 **모든 업체·항목·합계를 0점 고정**하도록 요청했다. 원본의 평가요소·배점·등급 설명은 유지하고 실제 업체별 점수만 0으로 출력한다. 새로운 신인도 입력 메뉴는 만들지 않았다. 협정보드의 기존 신인도 판정은 변경하지 않았다.

두 페이지의 표를 출력한다. 사용자 추가 수정으로 다음 상태가 최종이다.

- **`4. 신인도 평가` 제목은 첫 페이지에 딱 한 번만 표시한다.**
- 다음 페이지는 표만 이어진다. `(계속)`도, 두 번째 제목도 넣지 않는다.
- 표 안의 합계 행은 유지한다.
- 표 아래 별도 문구 **`신인도 평가합계 : 0점`은 삭제했다. 다시 넣지 않는다.**

총괄의 신인도는 0점이며, 수행능력 소계는 `시공경험 + 경영상태 + 신인도 + 하도급 + 자재`, 종합평점은 `소계 + 입찰가격`이다. 다른 점수 정보가 미완료이거나 지분이 맞지 않으면 종합평점을 임의로 채우지 않는다. 소계 50점·입찰가격 45점 → 총점 95점 사례를 검증했다.

### 5·6. 고정 양식

5번 표는 시행비율·금액비율의 배점한도가 **각각 5점**, 입찰자 평점은 기존 총괄 기준 **10점**이다. 등급 칸은 원본처럼 비워 둔다. 두 항목과 평가합계에 걸쳐 오른쪽 평점 칸을 병합했다.

원문 문구를 반영했다.

```text
다. 전문, 전기, 정보통신, 소방시설, 문화재공사 등의 하도급관리계획 적정성은 만점으로 평가한다.

6. 자재 및 인력조달 가격의 적정성 평가
※자재 및 인력조달 가격의 적정성 평가는 배점한도 점수를 부여한다.
```

총괄의 자재·인력조달도 기존 사용자 확정대로 LH 50억~100억에서 10점이다.

### 7. 입찰가격점수: 마지막 구현

원본 마지막 페이지와 `입찰가격.png`를 참고해 분수선, 절댓값 세로선, 괄호, 식의 단계별 위치, 최종 점수 밑줄, A값 설명을 구현했다. 공고정보의 `bidAmount`, `expectedPrice`, `aValue`를 사용한다.

```text
50 - 2 × abs((0.9 - (입찰가격 - A) / (예정가격 - A)) × 100)
```

실제 PDF는 `/` 텍스트가 아니라 **분자·가로선·분모**로 표시한다. 순서는 일반식 → 금액 대입 → A값 차감 후 금액 → 비율 대입 → 감점 → 최종 점수다. 공통 계산기의 `ratioRounded`와 저장된 점수를 그대로 표시한다.

- 비율은 소수 넷째 자리 반올림, 점수는 소수 둘째 자리다.
- 예시 입찰가격 `9,293,373,771`, 예정가격 `10,520,624,000`, A값 `704,658,655`.
- A 차감 후 `8,588,715,116 / 9,815,965,345` → `0.8750` → 감점 `5.00` → **45.00점**.
- A값 0원은 유효하다. 빈 값과 0을 혼동하지 않는다.
- 예정가격이 A 이하이거나 필요한 금액이 없으면 점수는 미산정이다. 양식에 다른 공고의 예시 값을 넣지 않는다.
- 원본 수식과 유사한 숫자 모양을 위해 PDF의 기본 Times-Roman/Times-Bold를 사용했다. 한글은 기존 Pretendard 임베딩이다.
- 미리보기에서 기본 숫자 글꼴이 대체되지 않도록 `public/pdf-standard-fonts/`에 `FoxitSerif.pfb`, `FoxitSerifBold.pfb`, `LICENSE_FOXIT`을 포함했다.
- `PdfDocumentPage.jsx`에서 `standardFontDataUrl`을 현재 문서 기준의 같은 출처 URL로 넘긴다. Vite 빌드 후 `dist/pdf-standard-fonts/`에 복사되는 것도 검증했다.
- Node에서 PDF.js 검사를 할 때는 `standardFontDataUrl`에 위 폴더의 절대 경로와 마지막 구분자를 주면 글꼴 경고를 피할 수 있다. 앱 미리보기에는 이미 설정되어 있다.

## 저장·불러오기·삭제

입력 초안은 브라우저 탭의 sessionStorage에 임시 보관한다. 명시적 저장은 웹 서버 JSON 저장소를 사용한다.

```text
기본 데이터 루트
/home/ihwijae/app-data/company-search

서류
${COMPANY_SEARCH_APP_DATA_ROOT}/document-generation/<UUID>.json

주요자재 설정
${COMPANY_SEARCH_APP_DATA_ROOT}/config/major-materials.json
```

환경변수 미지정 시 `~/app-data/company-search`를 사용한다. 위 데이터 폴더를 저장소에 커밋하지 않는다.

서류 JSON에는 `form`, `evaluationSnapshot`, `applicationSnapshot`, `overviewSnapshot`과 ID·제목·revision·생성/수정일 등이 들어간다. revision 충돌을 감지하며, 저장은 임시파일 작성 후 rename, 변경 작업은 큐로 직렬화한다. 사본 저장은 원본 기준을 이어받고 원본은 보존한다.

- 저장·불러오기·삭제 확인은 자체 UI다. 브라우저 기본 alert/confirm/prompt를 사용하지 않는다.
- 불러오기 모달은 검색·카드 목록·선택한 문서 요약·새로고침·선택한 서류 불러오기·선택한 서류 삭제를 지원한다.
- 삭제는 `DELETE /api/document-generation`에 `{ id, revision }`을 보내고, 자체 확인창을 거쳐 실제 JSON 파일을 삭제한다. 복구 UI는 없다.
- 다른 화면에서 수정된 서류를 오래된 revision으로 삭제하면 409를 반환한다.
- 현재 작성 중인 문서를 삭제해도 화면 입력은 유지하며, 저장 문서 연결을 끊고 다음 저장은 새 문서로 한다.
- 일반적으로 과거 기준과 결과는 스냅샷으로 보관한다. **품질평가 기본 전환 및 신인도 0점 연결은 사용자의 후속 명시 지시로 적용하는 예외**다.
- 문구·주소만 수정할 때 저장된 경영 판정을 다시 바꾸지 않도록 처리했다. 예전 신청서에 상세 내역이 없으면 저장된 기준으로 내역을 보강하되 기존 선택방법·점수를 보존한다.

## 주요자재 메뉴

상단 `주요자재`에서 자체 모달을 연다. 스위치류·콘센트류의 업체명·주소를 저장한다. 원본 PDF의 초기 4개 업체를 기반으로 했으며 항목 삭제·추가를 지원한다. 4개에서 하나를 지우면 3개가 저장되고 임의로 4칸으로 복원하지 않는다. 빈 배열도 저장 가능하다.

**주요 마감자재 선정 계획서 PDF 자체는 아직 생성하지 않는다.** 나중에 구현할 때 저장된 업체 개수에 맞춰 행을 출력해야 한다. 사용자 설명상 업체가 3개 또는 4개인 경우가 있다.

## 실행 환경과 이전 장애

```bash
npm run start:dev
```

이 명령은 Node 웹 서버(4173), Vite(5173), Python 백엔드(8787)를 함께 실행한다.

- 화면 개발 확인은 Vite 5173을 사용한다. 4173은 `dist`의 빌드된 화면이므로 소스를 바꿨다면 `npm run build`가 필요하다.
- 서버 API의 하위 저장 모듈은 실행 프로세스에 캐시된다. API 파일만 다시 로드되어도 하위 모듈까지 갱신되는 것은 아니다.
- 삭제 기능 추가 후 `deleteDocument is not a function` 오류가 발생한 것은 이전 모듈이 남아서였다. 백엔드 함수·저장 필드를 바꾸면 실행 중인 개발 스택을 재시작한다. 브라우저 새로고침만으로 해결되지 않는다.
- PDF worker 오류 `Setting up fake worker failed ... pdf.worker.min-....mjs`도 있었다. `server.js`에 `.mjs` JavaScript MIME을 추가했고, Vite의 복사된 `.mjs` 자산 이름을 `.js`로 내보내 기존 서버의 MIME 처리에서도 동작하도록 했다. worker 내용 자체를 변형하지 않는다.
- 사용자가 업체 시평·5년 실적이 이상하다고 했다가, **개발서버 DB와 비교 대상 DB가 달라 생긴 차이임을 확인하고 철회**했다. 이 이유로 원본 데이터 매핑을 다시 바꾸지 않는다.
- 운영 서버를 배포·재시작하지 않았다. 개발 확인만 진행했다.
