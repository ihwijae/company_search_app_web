# 메일 발송 기능 현황 (2025-02-14)

## 업체별 PC 폴더 생성 (2026-11-26 추가)

- 메일 화면의 `주소록` 버튼 옆에 `폴더생성` 버튼을 추가했다. 버튼을 누르면 서류생성 화면과 같은 디자인 방향의 전용 모달에서 저장 위치, 생성할 폴더 미리보기 및 처리 결과를 확인한다. 업체 목록에는 별도 패널을 표시하지 않는다.
- 사용자는 `폴더 선택`으로 자기 PC의 저장 기준 위치를 선택하고 쓰기 권한을 허용한다. 서버에 경로를 저장하거나 서버 폴더를 만드는 기능이 아니다.
- `폴더생성` 버튼을 누르면 SMTP 프로필을 먼저 검증한다. 프로필을 선택만 하고 불러오지 않았거나 선택 프로필이 불러온 프로필과 다르면 공통 안내를 띄우고 모달을 열지 않는다. 상위 폴더명에는 발신자 이름이 아닌 불러온 SMTP 프로필 이름을 사용한다.
- 엑셀을 정상적으로 불러온 뒤 모달에서 저장 위치와 생성할 폴더 구조를 확인하고 `폴더 생성`을 누른다. 선택한 저장 위치에 `공고명_내역서(프로필이름)` 폴더를 만들고 그 안에 `번호. 업체명` 폴더를 생성한다. 엑셀 불러오기만으로 폴더를 생성하지 않는다.
- 공고명은 정상적으로 읽은 엑셀 파일명에서 확장자(`.xlsx`, `.xlsm`, `.xls`)와 맨 끝의 `_투찰금액`만 제거해 구한다. 예: `2603745-00 남양주왕숙2 A-2BL 아파트 전기공사 2공구_투찰금액.xlsx` + 프로필 `홍길동` → `2603745-00 남양주왕숙2 A-2BL 아파트 전기공사 2공구_내역서(홍길동)`.
- 엑셀 읽기 실패, 아직 불러오지 않은 상태 및 ‘비우기’ 이후에는 파일명을 사용할 수 없으므로 엑셀을 다시 불러오라는 안내를 표시한다. 새로고침 후 복원된 업체 목록만으로는 폴더를 생성하지 않는다.
- 번호는 업체 목록의 `#` 값과 동일하다. `작업할업체만남기기`로 필터링하더라도 기존 업체 번호를 유지한다.
- 모달의 `작업할 업체 폴더만 남기기`를 누르면 불러온 SMTP 프로필 이름을 기준으로 담당 업체만 미리보기와 생성 대상으로 추린다. `전체 업체 보기`로 되돌릴 수 있다. 필터는 폴더 생성에만 적용하며 메일 수신자 목록은 유지한다.
- 담당 업체 필터를 적용했으나 일치하는 업체가 없으면 안내를 표시하고 생성 대상을 비운다. 일치하는 담당 업체가 없는 경우라도 프로필이 유효하면 모달을 열고 전체 업체 폴더를 생성할 수 있다.
- 기존 메일 목록의 `작업할업체만남기기`와 폴더 필터는 `services/recipientAssignment.js`의 공통 판정 로직을 사용한다. 기존 프로필 이름/성씨 매칭 및 업체별 작업자 정보 조회 규칙을 유지한다.
- 같은 이름의 공고 폴더와 업체 폴더가 있으면 재사용하고 기존 파일은 유지한다. 상위 공고 폴더를 만들 수 없으면 중단하며, 저장 기준 위치에 업체 폴더를 대신 만들지 않는다. 업체 폴더 이름과 충돌하는 파일이 있거나 생성에 실패한 업체는 결과의 실패 목록에 표시하고 나머지 업체는 계속 처리한다.
- 업체명이 비어 있는 행은 제외하고, Windows 폴더명에 사용할 수 없는 문자는 `_`로 대체하며 끝의 마침표와 공백은 제거한다.
- 저장 위치 선택은 현재 메일 화면을 사용하는 동안 유지된다. 화면을 다시 열거나 새로고침하면 다시 선택해야 한다. 브라우저 특성상 화면에는 전체 경로 대신 선택한 폴더 이름을 표시한다.
- PC용 Chrome/Edge의 HTTPS 또는 localhost 환경이 필요하다. 일반 HTTP LAN 주소에서는 지원 안내를 표시한다. 쓰기 권한이 해제되면 저장 폴더를 다시 선택하고 수동 생성을 실행한다.
- UI, 상태/권한 처리, 폴더 생성 로직은 각각 `components/VendorFolderDialog.jsx`, `hooks/useVendorFolders.js`, `services/vendorFolders.js`로 분리했다. 공통 `Modal`의 포커스 제어와 스크롤 잠금을 사용하며, 모달을 닫아도 선택한 저장 위치는 유지한다. 기존 엑셀 해석 및 메일 발송 규칙은 유지한다.

검증: `node scripts/verify-mail-vendor-folders.js`로 프로필 검증, 확장자/접미어 제거, 공고명과 프로필명 조합, 상·하위 폴더 생성, 번호 유지, 반복 생성, 기존 파일 보존, 파일명 충돌, 일부 실패 후 계속 생성, 권한 오류 및 진행률을 확인한다. 실제 브라우저의 폴더 선택/권한 허용과 버튼을 통한 생성은 사용자 PC에서 수동 확인이 필요하다.

## 완료된 주요 항목

### 메일 화면 스타일 정리 (2026-11-26)

- 왼쪽 설정 패널과 오른쪽 업체 목록, 버튼 순서, 표의 열 및 발송 흐름을 유지하고 메일 전용 `pages/MailAutomationPage.css`에서 화면 스타일을 정리했다.
- 화이트·슬레이트 바탕과 블루 강조색, 일관된 입력창과 버튼, 선형 아이콘, 담당자/첨부/상태 배지를 적용했다. 공고 정보는 기존 항목을 세로로 정렬해 읽기 쉽게 표시한다.
- 업체 목록 헤더를 고정하고 좁은 화면에서는 표를 가로로 스크롤한다. 업체 수를 제목 옆에 표시하고 비어 있는 목록의 안내를 정리했다.
- 주소록 별도 창, 템플릿 미리보기 및 발송 진행 창에도 같은 색상과 테두리 스타일을 적용했다. 파일 불러오기 영역은 키보드로도 실행할 수 있는 버튼을 사용한다.
- 주소록 창은 `components/MailAddressBookWindow.jsx`와 전용 CSS로 분리했다. 아이콘이 있는 상단 도구 모음, 검색어 초기화, 검색 결과 수와 저장 상태, 선택 행 강조, 고정된 목록 헤더와 독립 스크롤을 적용했다. 검색 결과가 없을 때와 주소록이 비어 있을 때 안내를 구분하며, 기존 주소 편집·저장·가져오기/내보내기·담당자 선택 동작은 유지한다. 별도 창에는 기존 `copyDocumentStyles`를 통해 스타일을 복사한다.
- 메일 화면·주소록·폴더 생성 모달의 글자 크기를 전반적으로 2px 키우고 입력창 및 버튼 높이도 조정했다. 본문/입력은 주로 14~15px, 작은 안내는 12~14px로 표시한다. 메일 본문 템플릿의 발송 결과에 포함되는 글꼴 크기는 변경하지 않는다.

1. **SMTP 통합 및 테스트 메일**
   - `nodemailer` 기반 SMTP 서비스(`src/main/features/mail/smtpService.js`) 구현.
   - `mail:send-test`, `mail:send-batch` IPC 추가로 테스트/일괄 발송 모두 지원.
   - 템플릿 치환값(제목/본문 HTML)을 그대로 적용하여 테스트 메일에서도 실제 스타일 확인 가능.

2. **일괄 발송 로직**
   - `MailAutomationPage.jsx`에서 수신자별 템플릿 치환 → SMTP 메시지 생성 → IPC로 전송.
   - 첨부파일을 복수개 누적하고, 발송 상태를 `대기/발송 중/완료/실패`로 표시.
   - 발송 중간에 오류가 발생해도 나머지 업체는 계속 진행되며, 실패 건은 실패 사유(예: 인증 오류)를 상태 메시지에 표시.

3. **주소록 개선**
   - `src/view/features/mail/addressBook.seed.json`을 기본값으로 사용하되, `loadPersisted('mail:addressBook')`으로 사용자 변경분을 저장/불러오기.
   - 주소록 모달에 검색, 가져오기(덮어쓰기), 내보내기, 저장(alert) 버튼 추가.
   - 업체명을 콤마로 구분해 여러 업체를 한 담당자에게 매핑 가능. 자동 매칭 시 동일 담당자가 여러 업체를 맡는 구조 지원.
   - 업체명 자동 매칭: 엑셀 불러오기/업체명 수정 시 주소록 인덱스를 조회해 담당자/이메일 자동 채움. 중복 담당자 발견 시 `담당자` 필드에 `[중복 확인] ...` 메시지를 넣어 사용자 확인 유도.

4. **템플릿 미리보기 & 공통 수신자 토글**
   - “치환 미리보기” 버튼으로 HTML 미리보기 모달 표시.
   - “받는사람에 팀장님 추가” 토글을 통해 조세희 상무님(`superssay@naver.com`)을 모든 메일의 `To` 헤더에 자동 포함.

5. **기타 편의 사항**
   - `받는사람에 팀장님 추가` 버튼의 상태를 즉시 표시(ON/OFF).
   - `비우기` 버튼으로 작성 중이던 프로젝트 정보/업체/첨부/템플릿을 한 번에 초기화할 수 있음.
   - SMTP 설정은 프로필로 저장/불러오기/삭제가 가능해 반복 입력 없이 재사용할 수 있음.
   - 주소록 모달/템플릿 미리보기 모달은 배경 클릭으로 닫히지 않고, 닫기 버튼으로만 닫힘.

## 다음에 고려할 만한 작업

1. **실패 건 재발송**: `상태`가 `실패`인 업체만 필터링해 다시 발송하는 기능.
2. **발송 로그 저장**: 메일 제목/수신자/결과/시간을 파일(JSON/CSV)로 남겨 추후 감사/확인을 쉽게 함.
3. **템플릿 HTML 에디터/치환 미리보기 고도화**: 현재 미리보기는 HTML만 보여주므로, 향후 CSS/브라우저 렌더링 차이에 대비해 iframe 기반 미리보기 등을 고려.
4. **주소록 입력 검증**: 이메일 형식 검증, 업체명 중복 경고 등 기본적인 검증 로직.
5. **실패 이유 알림**: 현재 상태 메시지에 첫 번째 실패 사유만 표시하므로, 리스트에서 개별 업체의 실패 사유를 hover/tooltip으로 보여주면 더 명확할 것.
