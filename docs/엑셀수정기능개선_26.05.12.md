# 엑셀수정 기능 개선 인계 - 2026.05.12

## 작업 배경

엑셀수정 웹 화면에서 PDF/이미지 뷰어 사용성, 스캔본 저장 속도, 화면 이동 후 업로드 파일 유지, 비율 표시 오류를 개선했다.

이번 작업은 웹 전용 구조를 기준으로 진행했으며 Electron/IPC 쪽 신규 의존은 추가하지 않았다.

## 수정 파일

- `backend/python/app/main.py`
- `src/shared/excelEditBackendClient.js`
- `src/view/features/excel-web/pages/ExcelWebEditPage.jsx`
- `src/styles.css`

## 구현 완료 내용

### 1. PDF/이미지 확대 제한 해제

기존에는 미리보기 확대값이 최대 `3`(300%)으로 제한되어 있었다.

- `previewZoom` 복원 시 `Math.min(3, ...)` 제거
- `changePreviewZoom()`의 최대값 제한 제거
- 축소 하한 `0.5`(50%)은 유지

추가로 150% 이후 실제 이미지가 더 커지지 않는 문제가 있었다. 원인은 flex item shrink 및 중앙 정렬 overflow 계산 문제였다.

- `.excel-web-v2-zoom-image`에 `flex: 0 0 auto` 추가
- PDF/이미지 스크롤 영역의 `justify-content`를 `center`에서 `flex-start`로 변경
- 이미지 자체에는 `margin: 0 auto`를 적용해서 기본 상태는 가운데에 보이게 유지

### 2. 이미지 미리보기 속도 개선

기존에는 JPG/PNG도 Python 백엔드에서 Pillow로 열고 PNG로 변환한 뒤 표시했다. 고해상도 JPG, 큰 스캔본, EXIF/CMYK가 섞인 파일에서 뷰어 표시가 늦어질 수 있었다.

변경 후:

- PDF는 계속 서버에서 페이지 렌더링
- JPG/PNG 이미지는 서버 변환 없이 브라우저가 원본 이미지 URL 또는 `File` 객체로 바로 표시
- 이미지 회전/확대/축소는 CSS transform 기반이라 그대로 동작

주의:

- 프론트에서 처리한다는 것은 미리보기만 해당한다.
- 서버 임시 저장 및 최종 보관 저장은 계속 수행한다.
- 뷰어 회전은 원본 파일 자체를 회전 저장하지 않는다.

### 3. 스캔본 임시 업로드 구조 추가

확정 및 저장 시점에 대용량 PDF/이미지를 다시 업로드하지 않도록 구조를 변경했다.

흐름:

1. 사용자가 PDF/이미지를 선택하면 즉시 서버 임시폴더에 저장
2. 프론트는 `uploadId`와 파일 메타데이터를 상태/sessionStorage에 보관
3. 화면 이동 후 돌아오면 `uploadId` 기반으로 파일 목록과 미리보기 복원
4. 확정 및 저장 시 `uploadId`를 백엔드에 전달
5. 백엔드는 임시파일을 최종 스캔본 보관 폴더로 이동
6. 초기화/파일 제거 시 임시파일 삭제 요청

추가된 백엔드 API:

- `POST /excel-edit/upload`
  - 기존 미리보기 검증용 API를 임시 저장 API로 변경
  - 응답에 `uploadId`, 원본명, 크기, contentType, 생성시각 포함
- `GET /excel-edit/temp-upload/{upload_id}`
  - 임시 업로드 메타 조회
- `GET /excel-edit/temp-upload/{upload_id}/content`
  - 임시 파일 원본 제공
- `POST /excel-edit/temp-uploads/delete`
  - `uploadIds` 배열을 받아 임시파일 삭제

환경변수:

- `EXCEL_EDIT_TEMP_UPLOAD_ROOT`
  - 임시 업로드 저장 루트
  - 기본값: `backend/python/data/temp-uploads`
- `EXCEL_EDIT_TEMP_UPLOAD_TTL_SECONDS`
  - 임시 업로드 만료 시간
  - 기본값: `86400`초(24시간)

임시파일 정리:

- 서버 시작 시 1회 정리
- 서버 실행 중 1시간마다 만료 파일 정리
- 사용자 초기화/파일 제거 시 즉시 삭제 요청
- 최종 저장 성공 시 임시파일 디렉터리 삭제

### 4. 확정 및 저장 체감 속도 개선

저장 완료까지 기다리던 작업 중 DB 재색인을 백그라운드로 분리했다.

기존:

1. 엑셀 반영
2. 스캔본 저장
3. 업로드 DB 재색인 완료 대기
4. 완료 알림

변경 후:

1. 엑셀 반영
2. 스캔본 임시파일 최종 보관 폴더로 이동
3. 완료 알림
4. 업로드 DB 재색인은 백그라운드 실행

주의:

- 원본 엑셀 저장과 스캔본 저장은 완료된 뒤 완료 알림을 띄운다.
- 재색인만 백그라운드다.
- 저장 직후 아주 짧은 시간 동안 검색/조회용 캐시가 이전 값일 수 있다.
- 재색인 실패 시 알림을 띄운다.

### 5. 저장 진행 상태 표시 추가

저장/업로드 중 사용자가 멈춘 것처럼 느끼지 않도록 상태 문구를 추가했다.

예:

- `스캔본을 서버 임시폴더에 업로드하는 중입니다.`
- `엑셀에 반영하고 스캔본을 최종 보관 폴더로 이동하는 중입니다.`
- `저장은 완료됐고, 검색용 데이터를 백그라운드로 갱신하는 중입니다.`

### 6. 새 PDF/이미지 업로드 시 업체정보 초기화

이미 PDF/이미지와 업체정보가 올라와 있는 상태에서 새 파일을 선택하면, 이전 업체정보를 보고 착각할 수 있어서 새 파일 업로드 성공 직후 다음 상태를 초기화한다.

- 기존 업체 조회 결과
- 변경 전 색상/표시 정보
- 저장 버전 정보
- 입력 텍스트칸 전체
- PDF 페이지 번호
- 미리보기 오류 상태

업로드 실패 시 기존 상태는 유지된다.

### 7. 유동비율 표시 오류 수정

증상:

- 엑셀에서는 유동비율이 `239.46%`로 보이는데, 엑셀수정에서 업체정보를 불러오면 `2.39%`로 표시됨

원인:

- 엑셀 셀 값이 `2.3946`이고 셀 서식이 `%`이면 Excel은 `239.46%`로 표시한다.
- 기존 백엔드는 셀의 `number_format`을 보지 않고 값 `2.3946`만 보고 `2.39%`로 표시했다.

수정:

- 업체 셀 추출 시 `numberFormat`도 같이 읽음
- `_format_ratio_for_display(value, number_format)`에서 `%` 서식이면 Excel 표시 방식처럼 `value * 100`으로 표시
- `부채비율`, `유동비율` 공통 적용

부채비율은 기존에 문제가 없었던 것으로 보이나, 공통 함수에서 Excel 서식 기준으로 보정하도록 정리했다.

## 남은 병목 및 다음 세션 추천 작업

아직 `확정 및 저장` 체감 속도가 느리다. 다음 세션에서는 아래를 우선 확인하는 것이 좋다.

### 1. Python 백엔드 엑셀 파일 로드 횟수 줄이기

현재 저장 흐름에서 여전히 같은 엑셀 파일을 여러 번 열 가능성이 있다.

대표 작업:

- `_validate_expected_version_for_save()`
- `_find_company_position()`
- `_extract_company_data()`
- `_extract_company_cells()`
- `_update_management_data_at_position()`

다음 개선 방향:

- 저장 요청 하나 안에서 workbook을 한 번 열고
- 업체 찾기
- 버전 검증
- 수정
- 업체명/지역 추출
- 저장

까지 한 흐름으로 묶는 구조를 검토한다.

특히 관리자료 수정은 일부 개선해서 이미 찾은 업체 위치를 재사용하도록 바꿨지만, 버전 검증 쪽에서 여전히 재검색/재로드가 발생할 수 있다.

### 2. 신용평가 저장 최적화

신용평가는 전기/통신/소방 DB 전체를 대상으로 찾고 저장한다.

확인할 점:

- 각 DB마다 workbook을 여러 번 여는지
- `_update_credit_data()`가 업체 찾기와 저장을 반복하며 병목이 되는지
- 업체 위치 캐시나 한 번 로드한 workbook 재사용이 가능한지

### 3. 스캔본 최종 이동 성능 확인

임시파일을 최종 폴더로 이동하도록 변경했지만, 저장 위치가 다른 디스크/마운트라면 `shutil.move()`가 내부적으로 copy+delete가 될 수 있다.

확인할 점:

- `EXCEL_EDIT_TEMP_UPLOAD_ROOT`와 `EXCEL_EDIT_ARCHIVE_ROOT`가 같은 파일시스템인지
- WSL 경로와 Windows 마운트 경로가 섞여 있지 않은지
- 큰 PDF에서 이동 시간이 실제로 얼마나 걸리는지

가능하면 임시폴더와 최종 보관 폴더를 같은 디스크/파일시스템에 두는 것이 좋다.

### 4. 저장 단계별 시간 로그 추가

다음 세션에서 병목을 정확히 보려면 `/excel-edit/save` 내부에 단계별 소요시간 로그를 추가하는 것이 좋다.

추천 로그 구간:

- 요청 파싱
- 버전 검증
- 업체 위치 검색
- 엑셀 값 수정
- workbook 저장
- 임시파일 최종 이동
- 응답 생성

로그 예:

```text
[excel-edit:save] validate=0.42s find=1.20s update=0.18s workbook_save=3.80s archive=0.05s total=5.75s
```

### 5. 오래된 임시파일 정책 확인

현재 기본 TTL은 24시간이다.

검토할 점:

- 현장 사용자가 업로드 후 하루 넘게 저장하지 않는 경우가 있는지
- 너무 오래 남는 것이 부담이면 6~12시간으로 줄일지
- 반대로 하루 이상 작업 보존이 필요하면 48시간 이상으로 늘릴지
